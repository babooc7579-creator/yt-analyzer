# Creator OS 정기 회귀 검수표

## 목적

업무 시스템 배포 뒤 기존 기능이 그대로 작동하는지 같은 순서로 확인합니다.
버튼 존재나 자동 테스트 통과와 실제 운영 화면 확인을 구분해 기록합니다.

## 공통 확인 순서

각 항목을 아래 순서로 확인합니다.

1. 화면 제목과 메뉴 이름이 일치하는가
2. 버튼을 실제로 누를 수 있는가
3. 누른 뒤 보이는 변화와 결과 위치가 명확한가
4. 조회·화면 이동·Azure DB 저장·YouTube API 호출 중 무엇인지 안내하는가
5. 빈 결과와 오류 뒤에 다시 진행할 방법이 있는가
6. 390×844 화면에서 페이지 전체 가로 넘침이 없는가
7. 저장이 필요한 항목은 저장 후 새로고침·재조회 결과까지 확인했는가

## 배포마다 확인할 핵심 흐름

| 흐름 | 확인할 결과 | 데이터 영향 | 현재 기준 |
|---|---|---|---|
| 오늘 볼 채널 → 수집 영상 목록 → 오늘의 레이더 | 선택 채널과 불러온 영상 수 유지 | Azure DB 조회, YouTube API 없음 | 운영 확인 |
| 수집 영상 목록 ↔ 소재 보관함 | 상단 제목·사이드바·작업 탭 일치 | 화면 이동 | 운영 확인 |
| 수집 영상 목록·발견함 빈 결과 복구 | 필터 초기화 후 원래 목록 표시 | 화면 필터 | 운영 확인 |
| 수집 영상 카드·리스트 보기와 다중 선택 | 보기 전환 뒤 선택 상태와 AI 요청문 작업 막대 표시 | 화면 표시·클립보드, API 없음 | 운영 확인 |
| 제작 후보함 → 대본 작업실 → 업로드 캘린더 | 같은 제작 후보로 왕복 | 화면 이동, 저장 버튼 전에는 쓰기 없음 | 운영 확인 |
| 최근 수집 상태 → 채널 운영실 | 선택한 채널과 관리·수집 단계 일치 | 화면 선택, 수집 자동 실행 없음 | 운영 확인 |
| 선택 채널 새 영상 수집 완료 안내 | 채널명·신규 영상 수·통계 갱신 수와 최근 수집 상태 이동 표시 | 승인된 실제 수집 1회, 자동 반복 없음 | 운영 확인 완료 (2026-07-29) |
| 설정 ↔ 업무 도구함 | 두 화면 제목과 왕복 버튼 일치 | 화면 이동, 외부 사이트 자동 실행 없음 | 로컬 클릭 확인 |
| 설정 미저장 이탈 | 경고 취소 시 화면과 초안 유지 | Azure DB 저장 없음 | 로컬 클릭 확인 |
| 새 채널 등록 빈 입력 | YouTube 확인 버튼 비활성화와 이유 표시 | API 호출·저장 없음 | 로컬 클릭 확인 |
| 새 채널 중복·오류 재시도 | 중복 저장 차단, 오류 후 다시 확인 가능 | 미리보기는 YouTube API 가능, 저장 전 차단 | 자동 테스트 확인 |
| 오래 열린 탭의 화면 파일 오류 | 빈 화면 대신 최신 화면 새로고침 안내 | 새로고침 전 데이터 변경 없음 | 코드·자동 테스트 확인 |
| 레이더 판단 기록 정리 | 개별 `레이더로 되돌리기`만 사용 가능하고 전체 초기화는 노출되지 않음 | 제작 후보·대본·업로드 일정 보존 | 코드·자동 테스트 확인 |

## 매일 3분 확인 순서

아래 순서는 저장·삭제와 YouTube 신규 수집 없이 매일 핵심 업무 흐름을 빠르게 확인합니다.

1. `오늘 볼 채널`에서 채널 1개를 선택합니다.
2. `선택 채널 수집 영상 목록 불러오기`로 온라인 저장소(Azure DB)의 기존 영상 정보를 조회합니다.
3. `수집 영상 목록`에서 영상 2개 선택 → `AI 요청문 복사` → 복사 완료 안내 → `선택 해제`를 확인합니다.
4. `오늘의 레이더`에서 후보와 기존 판단 기록을 확인하고 `제작 후보함`의 같은 원본으로 이동합니다. 상태 변경 버튼은 누르지 않습니다.
5. `최근 수집 상태`에서 실행 요약을 펼치고 `이 채널 관리`로 선택 채널이 연결되는지 확인합니다.

공통 확인:

- 일부 온라인 저장 기능 경고가 있으면 경고 메시지에 적힌 기능만 영향받는지 확인합니다.
- `npm run test:daily`로 경고 범위, 조회 재시도, 필터·선택, 복사·선택 해제, 모바일 리스트와 수집 완료 결과 안전 계약을 먼저 확인합니다.
- GitHub의 `Core read-only regression check`는 PR 생성과 `main` 반영 때 실행됩니다. 매일 예약 실행되는 작업은 아니며, 매일 점검할 때는 사용자가 `npm run test:daily`를 직접 실행합니다.
- 필터를 적용하면 적용 개수와 `필터 초기화`가 나타나고, 초기화 뒤에도 영상 선택 수가 유지되는지 확인합니다.
- 모바일 리스트는 제목·조회수·대박 지수·게시일과 핵심 작업만 표시하고 페이지 전체 가로 넘침이 없는지 확인합니다.
- 일부 온라인 저장 기능 경고의 `영상 판단 기록 다시 확인`과 `소재 보관함 다시 확인`은 해당 Azure DB 읽기만 재실행하고 저장·삭제는 하지 않습니다.
- 실제 쓰기 검수와 YouTube 신규 수집은 아래 별도 승인 항목으로 분리합니다.

## 별도 승인이 필요한 실제 쓰기 검수

아래 항목은 테스트 대상을 정한 뒤 사용자의 별도 승인으로 실행합니다.

- 대본 기록 Azure DB 저장 → 새로고침 → 재조회 유지
- 업무 도구 설정 Azure DB 저장 → 다른 화면·다른 브라우저 반영
- 채널 등록 Azure DB 저장 → 채널 목록 재조회
- 발견 링크와 제작 후보 상태 저장 → 재조회 유지
- YouTube 신규 수집 → 실행 결과와 Azure DB 반영

YouTube 신규 수집을 승인받아 실행한 경우에는 같은 화면의 완료 안내에서 대상 채널, 신규 영상 수, 기존 영상 통계 갱신 수를 확인하고 `최근 수집 상태에서 자세히 보기`가 API 재호출 없이 결과 화면으로 이동하는지 함께 기록합니다.
