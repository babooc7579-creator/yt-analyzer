# Creator OS 상태값 사전

작성일: 2026-07-02

이 문서는 Creator OS에서 사용하는 상태값을 "현재 구현 기준"과 "목표 기준"으로 나누어 정리한 운영 기준입니다.

상태값은 화면 표시만의 문제가 아닙니다. 어떤 영상이 레이더에서 숨겨지는지, 어떤 채널이 스캔 대상인지, 어떤 소재가 제작 후보인지, 어떤 데이터가 Cloud DB에 저장되는지에 직접 영향을 줍니다.

이 문서는 코드 변경 없이 현재 상태를 고정하고, 다음 리팩터링과 기능 확장을 안전하게 나누기 위해 작성합니다.

---

## 1. 현재 기준 사실

아래 내용은 2026-07-02 기준 데이터 소유권 문서와 Backend/API Evidence Audit을 기준으로 합니다.

- `/video-records` 백엔드는 단일 `status` 중심입니다.
- 프론트는 `statusIds`를 일부 사용하고, `status`를 `statusIds`처럼 해석하는 호환 함수를 가지고 있습니다.
- 2026-07-02 선택지 B 승인 이후, 현재 단계에서는 기존 `status`를 대표 상태로 유지하고 `statusIds`를 복수 판단 보존용으로 함께 저장/조회하는 방향으로 정리 중입니다.
- `production_candidates` 별도 저장소는 없습니다.
- 제작 후보와 제작 칸반은 현재 `videoUserRecords` 상태값 위에서 표현됩니다.
- `scan_logs` 별도 저장소는 없습니다.
- 수집 상태는 현재 채널 문서의 `lastScanSummary.status` 중심입니다.
- `discovery_links`와 `local_assets`는 아직 미구현입니다.
- 화면/메뉴의 `live`, `soon`은 제품 UI 상태이며 영상/채널/제작 상태와 섞으면 안 됩니다.

## 2. 상태값 분류 원칙

Creator OS의 상태값은 다음처럼 분리합니다.

| 분류 | 목적 | 현재 저장 위치 | 목표 저장 위치 | 현재 구현 |
|---|---|---|---|---|
| 채널 등급 | 채널 중요도 판단 | `channels.grade` | `channels.grade` | 구현됨 |
| 채널 상태 | 수집 대상 여부 | `channels.status` | `channels.status` | 구현됨 |
| 영상 검토 상태 | 레이더/영상 목록에서 사용자의 판단 기록 | `videoUserRecords.status`, 프론트 `statusIds` 호환 | Cloud DB의 영상별 사용자 기록 | 부분 구현 |
| 제작 후보 상태 | 후보에서 업로드까지 제작 흐름 관리 | `videoUserRecords.status` 위에 얹힘 | 미정. MVP는 `videoUserRecords`, 장기는 별도 모델 검토 | 부분 구현 |
| 수집 상태 | 스캔 성공/실패/부분 성공 표시 | `channels.lastScanSummary.status` | `scan_logs` 후보, 현재는 채널 마지막 요약 | 부분 구현 |
| 스크랩북 상태 | 저장됨/삭제됨 여부 | `scrapbook` 문서 존재 여부 | Cloud DB 기준 | 부분 구현 |
| 발견 링크 상태 | 외부 링크의 검토/출처 상태 | 없음 | `discovery_links` 후보 | 미구현 |
| 로컬 파일 출처 상태 | 다운로드 파일의 원본/권리/연결 상태 | 없음 | `local_assets` 후보 | 미구현 |
| 화면/메뉴 상태 | 메뉴 사용 가능 여부 표시 | `creatorOs.js` 상수 | UI 구성 상수 | 구현됨 |

## 3. 채널 등급 `channel.grade`

채널 등급은 "중요한 채널인가"를 표시하는 판단 보조값입니다. 수집 가능 여부를 직접 의미하지 않습니다.

현재 저장 위치:

- Cloud DB `channels` container
- 프론트 상수: `CHANNEL_GRADE`

| 저장값 | 화면 표시 | 현재 의미 | 목표 의미 | 판단 |
|---|---|---|---|---|
| `S` | S | 핵심 채널 | 매일 또는 자주 참고할 핵심 벤치마크 | 유지 |
| `A` | A | 중요 채널 | 자주 확인할 우선 채널 | 유지 |
| `B` | B | 일반 참고 채널 | 눈여겨볼 채널 | 유지 |
| `C` | C | 낮은 우선순위 채널 | 가끔 참고할 채널 | 유지 |
| `unclassified` | 미분류 | 아직 판단 전 | 기본값 | 유지 |

운영 원칙:

- `grade`는 중요도입니다.
- `grade`만으로 API 호출을 늘리지 않습니다.
- 자동 스캔 주기와 연결하는 것은 나중에 별도 판단합니다.
- S등급이어도 `status`가 `paused`이면 스캔 대상에서 제외될 수 있습니다.

---

## 4. 채널 상태 `channel.status`

채널 상태는 "이 채널을 수집 대상으로 볼 것인가"를 정하는 운영값입니다.

현재 저장 위치:

- Cloud DB `channels` container
- 프론트 상수: `CHANNEL_STATUS`
- 백엔드 스캔 로직은 `active` 채널만 스캔 대상으로 봅니다.

| 저장값 | 화면 표시 | 현재 의미 | 목표 의미 | 스캔 대상 |
|---|---|---|---|---|
| `active` | 활성 | 정상 수집 대상 | 계속 추적할 채널 | 예 |
| `paused` | 보류 | 수집 제외 | 나중에 재검토할 채널 | 아니오 |
| `discarded` | 제외 | 수집 제외 | 더 이상 보지 않을 채널 | 아니오 |

운영 원칙:

- `status`는 API 호출 대상 여부와 연결됩니다.
- 사용자는 `paused`와 `discarded`의 차이를 화면에서 이해할 수 있어야 합니다.
- 상태 변경은 기존 영상 데이터를 삭제하는 작업이 아닙니다.

---

## 5. 영상 검토 상태

영상 검토 상태는 사용자가 영상을 보고 내린 판단입니다.

현재 저장 위치:

- 백엔드: `/video-records`의 단일 `status`
- 프론트: `status`와 `statusIds`를 함께 해석하는 호환 구조
- localStorage: 기존 호환/복구 보조

현재 확인된 위험:

- 프론트는 복수 상태처럼 다루지만, 백엔드는 단일 `status` 중심입니다.
- `statusIds`를 기준 구조로 확정하려면 백엔드 schema 판단이 먼저 필요합니다.
- 지금 당장 단일 `status`를 제거하면 기존 레이더와 제작 칸반 흐름이 깨질 수 있습니다.

| 저장값 | 화면 표시 | 현재 의미 | 목표 의미 | 현재 판단 |
|---|---|---|---|---|
| `unseen` | 아직 안 봄 | 아직 검토하지 않음 | 기본 미검토 | 유지 |
| `opened` | 유튜브 열어봄 | 링크를 열어봄 | 가볍게 확인함 | 유지 |
| `reviewed` | 봤음 | 검토 완료, 레이더 숨김 후보 | 확인함 | 표시명 개선 후보 |
| `watch_later` | 나중에 보기 | 다시 볼 영상 | 다시 보기 | 유지 |
| `later` | 나중에 보기 | 기존 호환값 | `watch_later`로 흡수 후보 | 레거시 호환 유지 |
| `production_candidate` | 제작 후보 | 제작 후보로 보냄 | 제작 후보 | 유지 |
| `reference_material` | 자료 참고 | 참고 자료 | 자료 참고 | 유지 |
| `title_reference` | 제목 참고 | 제목 아이디어 참고 | 제목 참고 | 유지 |
| `excluded` | 제외 | 레이더/목록에서 숨김 | 제외 | 유지 |
| `used` | 사용함 | 이미 사용한 소재 | 사용함 | 유지 |

운영 원칙:

- 지금은 `status`와 `statusIds`를 함께 읽는 호환 구조를 유지합니다.
- 현재 단계에서는 `status`를 대표 상태로 유지하고, `statusIds`는 복수 판단 보존용 보조 필드로 봅니다.
- 레이더에서 숨겨지는 상태는 별도 목록으로 관리합니다.
- `later`는 기존 데이터 호환용 값으로 보고, 새 표시명은 `watch_later` 중심으로 정리합니다.

## 6. 제작 후보 상태

제작 후보 상태는 "이 소재를 실제 콘텐츠 제작 흐름에서 어디까지 진행했는가"를 표현합니다.

현재 저장 위치:

- 별도 `production_candidates` 저장소 없음
- 현재는 `videoUserRecords`의 상태값 위에서 제작 칸반이 동작

| 저장값 | 화면 표시 | 현재 의미 | 목표 의미 | 현재 판단 |
|---|---|---|---|---|
| `production_candidate` | 제작 후보 | 후보로 등록됨 | 제작 후보 | MVP 유지 |
| `production_reviewing` | 검토 중 | 프론트 상수 존재 | 제작 전 검토 중 | 부분 구현 |
| `production_decided` | 제작 결정 | 프론트 상수 존재 | 만들기로 결정 | 부분 구현 |
| `production_active` | 제작 중 | 제작 중 | 제작 진행 중 | 유지 |
| `uploaded` | 업로드 완료 | 업로드 완료 | 완료 | 유지하되 `used`와 구분 필요 |
| `production_on_hold` | 보류 | 프론트 상수 존재 | 제작 보류 | 부분 구현 |

운영 원칙:

- 지금은 별도 `production_candidates` DB를 만들지 않습니다.
- 제작 상태는 영상 검토 상태와 의미가 다릅니다.
- 장기적으로 한 제작물이 여러 원본 영상, 발견 링크, 로컬 파일을 묶어야 하면 별도 모델이 필요할 수 있습니다.
- `uploaded`는 제작 완료 상태이고, `used`는 영상 소재가 사용되었다는 상태입니다. 둘은 같지 않습니다.

## 7. 수집 상태

수집 상태는 YouTube API를 호출해 새 영상이나 통계를 가져온 결과를 표시합니다.

현재 저장 위치:

- `channels.lastScanSummary.status`
- 별도 `scan_logs` 저장소 없음

| 저장값 | 화면 표시 | 현재 의미 | 목표 의미 | 현재 판단 |
|---|---|---|---|---|
| `success` | success | 수집 성공 | 성공 | 유지 |
| `partial` | partial | 일부 부족하거나 누락 가능 | 부분 성공 | 유지 |
| `failed` | failed | 수집 실패 | 실패 | 유지 |
| `none` | none | 수집 기록 없음 | 기록 없음 | UI 파생값으로 유지 |

운영 원칙:

- 현재는 마지막 수집 요약만 남습니다.
- 과거 이력은 추적하지 못합니다.
- 수집 로그 화면을 만들려면 `scan_logs` 모델이 필요합니다.
- 수집 상태는 영상 상태나 제작 상태와 섞으면 안 됩니다.

## 8. 스크랩북 상태

스크랩북은 현재 명시적인 상태값보다 "문서가 존재하는가"로 판단됩니다.

현재 저장 위치:

- Cloud DB `videos` container 안의 `docType: scrapbook`
- localStorage는 기존 호환/복구 보조

| 상태 | 현재 표현 | 목표 표현 | 현재 판단 |
|---|---|---|---|
| 저장됨 | scrapbook 문서 존재 | saved | 구현됨 |
| 삭제됨 | scrapbook 문서 삭제 | removed 또는 없음 | 구현됨 |
| 동기화 실패 | 명시 상태 없음 | sync_failed 후보 | 미구현 |

운영 원칙:

- 지금은 별도 `scrapbook.status`를 만들지 않습니다.
- 스크랩북 기준 데이터는 Cloud DB로 옮겨가는 중입니다.
- localStorage 삭제나 key 변경은 별도 Issue에서 판단합니다.

## 9. 발견 링크 상태

발견 링크는 아직 구현되어 있지 않은 목표 모델입니다.

목표 후보 상태:

| 저장값 후보 | 화면 표시 | 의미 |
|---|---|---|
| `new` | 새 링크 | 아직 확인하지 않은 링크 |
| `reviewing` | 확인 중 | 출처와 소재성을 검토 중 |
| `source_candidate` | 원본 후보 | 원본일 가능성이 있는 링크 |
| `repost_suspected` | 리포스트 의심 | 원본이 아닐 가능성이 있음 |
| `rights_check_needed` | 권리 확인 필요 | 사용 전 권리 확인 필요 |
| `production_candidate` | 제작 후보 | 제작 후보로 보낼 수 있음 |
| `discarded` | 제외 | 더 이상 보지 않음 |

운영 원칙:

- 무단 크롤링이나 자동 다운로드를 전제로 하지 않습니다.
- 링크 저장과 원본 확인은 수동 판단 중심으로 시작합니다.
- API 구현은 별도 결정이 필요합니다.

---

## 10. 로컬 파일 출처 상태

로컬 파일 출처 상태는 아직 구현되어 있지 않은 목표 모델입니다.

목표 후보 상태:

| 저장값 후보 | 화면 표시 | 의미 |
|---|---|---|
| `unlinked` | 링크 없음 | 파일만 있고 출처 링크가 없음 |
| `linked` | 링크 연결됨 | 원본 또는 참고 링크가 연결됨 |
| `source_unknown` | 출처 불명 | 출처를 알 수 없음 |
| `source_verified` | 출처 확인 | 출처 확인 완료 |
| `rights_check_needed` | 권리 확인 필요 | 사용 전 확인 필요 |
| `ready_for_reference` | 참고 가능 | 내부 참고용으로 사용 가능 |

운영 원칙:

- 로컬 파일 자체를 Cloud DB에 저장한다는 뜻이 아닙니다.
- Cloud DB에는 파일 메타데이터와 연결 정보만 저장하는 방향을 검토합니다.
- 브라우저 앱에서 로컬 파일 경로를 안정적으로 관리할 수 있는지 별도 검토가 필요합니다.

## 11. 화면/메뉴 상태

화면/메뉴 상태는 제품 UI의 준비 상태입니다. 데이터 상태와 다릅니다.

현재 저장 위치:

- 프론트 `creatorOs.js` 상수

| 저장값 | 화면 의미 | 주의 |
|---|---|---|
| `live` | 현재 사용 가능 | 실제 API/DB 동작이 있는 화면에만 사용 |
| `soon` | 준비 중 | 클릭해도 API 호출이나 DB 변경이 없어야 함 |

운영 원칙:

- `live`와 `soon`은 영상, 채널, 제작 후보 상태로 쓰지 않습니다.
- 준비중 화면은 실제 기능처럼 오해되지 않아야 합니다.

---

## 12. 상태값 충돌 위험

현재 가장 큰 위험은 다음입니다.

1. `status`와 `statusIds` 불일치
2. 영상 검토 상태와 제작 후보 상태 혼합
3. `uploaded`와 `used` 의미 혼동
4. `later`와 `watch_later`, `production_on_hold` 의미 혼동
5. 수집 상태와 영상 상태 혼동
6. 준비중 메뉴를 실제 기능처럼 보이게 하는 위험

## 13. 지금 결정하지 말아야 할 것

아래 항목은 이 문서에서 결정하지 않습니다.

- `status`와 `statusIds`를 `lifecycleStatus`, `usagePurposeTags`, `productionStatus`로 분리할지 여부
- 기존 `status`를 언제 제거할지 여부
- `production_candidates` 별도 DB 도입 여부
- `uploaded`를 `done`으로 바꿀지 여부
- `later` 기존 데이터를 어떻게 마이그레이션할지 여부
- `discovery_links` 상태값 최종 확정
- `local_assets` 상태값 최종 확정
- `scan_logs` 또는 `api_quota_logs` container 추가

이 항목은 제품 판단과 데이터 안전성이 걸려 있으므로 별도 선택지 보고 후 결정합니다.
