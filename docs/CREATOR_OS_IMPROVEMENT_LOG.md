# Creator OS 개선 기록 운영 기준

## 목적

Creator OS를 고도화할 때 현재 상태, 목표 방향, 다음 작업, 결정 필요 사항을 잃지 않도록 관리합니다.
기능이 많아지는 것보다 실제 사용자 흐름과 이름·동작·데이터 결과가 일치하는지를 우선합니다.

## 2026-08-03 YouTube 검색 편의 보강

- 영상·채널 검색에 `대한민국·한국어 우선 빠른 설정`을 추가했습니다. 설정만 바꾸며 검색 버튼을 누르기 전에는 YouTube API를 호출하지 않습니다.
- 마지막 검색 뒤 키워드·검색 지역·우선 언어 등 API 검색 조건을 바꾸면 `검색 조건이 바뀌었습니다` 안내를 표시합니다. 기존 결과와 새 선택 조건이 섞여 보이는 혼동을 줄입니다.
- 채널 검색 결과를 구독자 수·영상당 평균·영상 수 기준으로 화면에서 정렬할 수 있습니다. 이미 받은 결과의 순서만 바꾸며 API를 다시 호출하지 않습니다.
- 채널 카드에 채널 운영자가 YouTube에 등록한 국가를 표시하고, 값이 없으면 `미등록`으로 표시합니다. 검색 지역과 채널 설정 국가는 서로 다른 정보입니다.
- 한국어 영상만 남기는 엄격한 필터는 언어 정보가 비어 있는 영상까지 숨길 위험이 있어 별도 결정 전에는 추가하지 않습니다.
- 운영 배포 후 `바이브 코딩`·대한민국·한국어 우선 채널 검색을 한 번 실행해 12개 결과, 채널 설정 국가, 화면 정렬과 조건 변경 안내를 확인했습니다. 등록·온라인 저장은 실행하지 않았습니다.
- PR #1052 배포 후 같은 조건으로 채널 검색을 한 번만 실행해 새 화면 필터를 검수했습니다. 국가 미등록 필터는 4개 결과를 표시했고, 등록·국가 조합으로 0개가 되면 원본 결과를 지우지 않은 채 초기화 안내가 나타났습니다.
- 비교 1개 선택 시 구독자·영상 수·누적 조회수·영상당 평균과 등록·국가 상태가 함께 표시됐고, 전체 해제도 정상 작동했습니다.
- 390×844 모바일에서 결과 카드·필터·정렬·작업 영역은 페이지 가로 넘침이 없었습니다. 오늘의 레이더에 다녀온 뒤에도 12개 결과, 영상당 평균순, 국가 미등록 필터, 비교 선택이 유지됐으며 추가 YouTube 검색은 실행되지 않았습니다.

비교 요약은 채널을 선택한 뒤 실제 결정을 내리는 곳입니다. 이제 각 비교 채널에서 `등록 검토`, `YouTube 보기`, `비교에서 빼기`를 바로 사용할 수 있습니다. 등록 검토는 기존처럼 채널 운영실 입력만 준비하고 자동 확인·저장·영상 수집은 실행하지 않습니다.

로컬 최신 production 코드에 화면 전용 모의 채널 2개를 넣어 실제 버튼 동작을 검수했습니다. 390×844에서 문서 너비 375px로 가로 넘침이 없었고, 비교 요약의 등록 검토가 정확한 채널 URL을 채널 운영실 입력에 전달했습니다. 키워드 탐색으로 돌아온 뒤 결과 2개와 비교 선택 1개가 유지됐습니다. 모의 응답은 검수 탭에만 적용했고 앱 코드·Azure DB·YouTube 데이터에는 남지 않았습니다.

사용자 결정으로 비교 선택은 최대 4개를 유지하고 등록 후보 선택은 최대 50개로 분리했습니다. 검색 결과에서는 후보만 고르고 기존 채널 운영실 일괄 추가 화면에서 태그·언어와 최종 저장을 확인합니다. 백엔드는 최대 50개를 10개씩 확인하며 기존 등록 채널·같은 요청의 중복 입력은 다시 저장하지 않습니다. 결과는 새로 저장·기존 등록·중복 입력·실패로 채널별 표시하며 영상 수집은 실행하지 않습니다.

## 화면과 기록 원본

- 사용자 화면: `인사이트 / 학습 → 개선 기록`
- 구조화된 기록 원본: `src/constants/improvementLog.js`
- 화면 컴포넌트: `src/components/ImprovementLogWorkspace.jsx`
- 정기 검수 기준: `docs/CREATOR_OS_REGRESSION_CHECKLIST.md`
- 변경 추적: Git 커밋과 Pull Request

개선 기록 화면은 읽기 전용입니다. 화면을 열어도 API 호출, 온라인 저장소(Azure DB) 조회·저장,
YouTube API 수집, localStorage 변경이 발생하지 않습니다.

## 완료 판단 기준

아래를 필요한 범위까지 확인한 뒤에만 `확인 완료`로 바꿉니다.

1. 코드 또는 버튼이 존재합니다.
2. 실제로 클릭할 수 있습니다.
3. 사용자가 화면에서 변화를 확인할 수 있습니다.
4. 결과 위치와 다음 행동이 명확합니다.
5. 버튼 이름과 실제 기능이 일치합니다.
6. 필요한 경우 API 호출과 온라인 저장소(Azure DB) 결과를 확인했습니다.
7. YouTube 신규 수집과 Azure DB 조회·저장을 구분했습니다.

## 메뉴 역할과 확인 상태

개선 기록 화면의 `메뉴 역할표`에서 다음을 함께 관리합니다.

- 메뉴가 존재하는 이유
- 실제 데이터·동작 경계
- 운영 클릭, 로컬 클릭, 코드·테스트, 결정 필요 중 현재 확인 수준

운영 화면을 누르지 않은 기능은 코드나 테스트가 있어도 `운영 클릭 확인`으로 표시하지 않습니다.

## 대본 작업실 현재 기준

- 제작 후보함: 무엇을 만들지 결정합니다.
- 대본 작업실: 결정한 소재를 어떻게 만들지 분석·작성·수정합니다.
- 업로드 캘린더: 언제 올릴지 확인합니다.
- AI 공방: 이후 분석과 작성 제안을 보조합니다.

현재 백엔드는 기존 `draftTitle`, `note`, `targetPublishDate`와 함께
`scriptAnalysis`, `scriptOutline`, `scriptBody`, `scriptStatus`를 보존합니다.
기존 `note`는 변환하거나 삭제하지 않고 `기존 통합 작업 메모`로 유지합니다.
수정 이력, 이전 버전 비교, AI 보조는 개인용 MVP 이후의 별도 작업입니다.

## 2026-07-28 완료한 1~5번 연결 검수

- 발견함에서 제작 후보로 표시한 링크는 제작 후보함에 이미 연결돼 있습니다.
- 제작 후보함의 링크 카드에 `대본 작업 시작`을 추가해 같은 링크를 대본 작업실 원본으로 사용합니다.
- 링크 대본은 새 DB나 endpoint 없이 기존 `videoUserRecords`에 `discovery-link:<기존 링크 ID>` 형태의 안정적인 작업 ID로 저장합니다.
- 링크 원본 URL과 제목은 기존 온라인 발견함(Azure DB) 기록을 계속 기준으로 사용합니다.
- `태그별 금고`는 별도 저장 장소로 오해되지 않도록 `채널 태그별 보기`로 바꾸고, 전체 수집 영상 목록으로 돌아가는 버튼을 연결했습니다.
- 오늘의 레이더에서 제작 후보가 생기면 제작 후보함, 대본 작업실, 업로드 캘린더로 바로 이어갈 수 있게 합니다.
