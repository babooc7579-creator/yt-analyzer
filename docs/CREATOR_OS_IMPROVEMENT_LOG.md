# Creator OS 개선 기록 운영 기준

## 목적

Creator OS를 고도화할 때 현재 상태, 목표 방향, 다음 작업, 결정 필요 사항을 잃지 않도록 관리합니다.
기능이 많아지는 것보다 실제 사용자 흐름과 이름·동작·데이터 결과가 일치하는지를 우선합니다.

## 화면과 기록 원본

- 사용자 화면: `인사이트 / 학습 → 개선 기록`
- 구조화된 기록 원본: `src/constants/improvementLog.js`
- 화면 컴포넌트: `src/components/ImprovementLogWorkspace.jsx`
- 정기 검수 기준: `docs/CREATOR_OS_REGRESSION_CHECKLIST.md`
- 변경 추적: Git 커밋과 Pull Request

개선 기록 화면은 읽기 전용입니다. 화면을 열어도 API 호출, 온라인 저장소(Azure DB) 조회·저장,
YouTube API 수집, localStorage 변경이 발생하지 않습니다.

## 체크포인트 상태

| 상태 | 의미 |
|---|---|
| 확인 완료 | 실제 구현과 사용자에게 보이는 결과를 확인했습니다. |
| 진행 중 | 일부가 구현됐지만 검수나 후속 작업이 남았습니다. |
| 결정 필요 | 데이터 구조, 메뉴 통합, 비용 또는 사용자 선택이 필요합니다. |
| 진행 예정 | 방향은 정해졌으며 앞선 작업 뒤에 진행합니다. |
| 나중에 | 개인용 MVP 이후로 미룹니다. |

## 완료 판단 기준

아래를 필요한 범위까지 확인한 뒤에만 `확인 완료`로 바꿉니다.

1. 코드 또는 버튼이 존재합니다.
2. 실제로 클릭할 수 있습니다.
3. 사용자가 화면에서 변화를 확인할 수 있습니다.
4. 결과 위치와 다음 행동이 명확합니다.
5. 버튼 이름과 실제 기능이 일치합니다.
6. 필요한 경우 API 호출과 온라인 저장소(Azure DB) 결과를 확인했습니다.
7. YouTube 신규 수집과 Azure DB 조회·저장을 구분했습니다.

## 기능 변경 시 갱신 순서

1. 변경 대상 영역의 현재 체크포인트를 읽습니다.
2. 이번 변경 범위와 완료 기준을 정합니다.
3. 코드와 테스트를 작은 단위로 수정합니다.
4. 운영 화면에서 실제 결과를 확인합니다.
5. `src/constants/improvementLog.js`의 상태, 다음 작업, 마지막 점검일을 갱신합니다.
6. 중요한 결정은 `decisions`에 남깁니다.
7. `docs/HANDOFF.md`와 `docs/WORK_LOG.md`에 실제 완료 내용을 기록합니다.

## 메뉴 역할과 확인 상태

개선 기록 화면의 `메뉴 역할표`에서 다음을 함께 관리합니다.

- 메뉴가 존재하는 이유
- 실제 데이터·동작 경계
- 운영 클릭, 로컬 클릭, 코드·테스트, 결정 필요 중 현재 확인 수준

운영 화면을 누르지 않은 기능은 코드나 테스트가 있어도 `운영 클릭 확인`으로 표시하지 않습니다.

## 대본 작업실 현재 기준

- 제작 후보함: 무엇을 만들지 결정합니다.
- 대본 작업실: 결정한 소재를 어떻게 만들지 분석·작성·수정합니다.
- 업로드 캘린더: 언제 올릴지 확인합니다.
- AI 공방: 이후 분석과 작성 제안을 보조합니다.

현재 백엔드는 기존 `draftTitle`, `note`, `targetPublishDate`와 함께
`scriptAnalysis`, `scriptOutline`, `scriptBody`, `scriptStatus`를 보존합니다.
기존 `note`는 변환하거나 삭제하지 않고 `기존 통합 작업 메모`로 유지합니다.
수정 이력, 이전 버전 비교, AI 보조는 개인용 MVP 이후의 별도 작업입니다.

## 2026-07-28 완료한 1~5번 연결 검수

- 발견함에서 제작 후보로 표시한 링크는 제작 후보함에 이미 연결돼 있습니다.
- 제작 후보함의 링크 카드에 `대본 작업 시작`을 추가해 같은 링크를 대본 작업실 원본으로 사용합니다.
- 링크 대본은 새 DB나 endpoint 없이 기존 `videoUserRecords`에 `discovery-link:<기존 링크 ID>` 형태의 안정적인 작업 ID로 저장합니다.
- 링크 원본 URL과 제목은 기존 온라인 발견함(Azure DB) 기록을 계속 기준으로 사용합니다.
- `태그별 금고`는 별도 저장 장소로 오해되지 않도록 `채널 태그별 보기`로 바꾸고, 전체 수집 영상 목록으로 돌아가는 버튼을 연결했습니다.
- 오늘의 레이더에서 제작 후보가 생기면 제작 후보함, 대본 작업실, 업로드 캘린더로 바로 이어갈 수 있게 합니다.
- 운영에서 발견 링크 후보 → 대본 작업실 → 업로드 캘린더와 채널 태그별 보기 → 전체 수집 영상 목록 이동을 확인했습니다.
- 대본 작업실의 입력이 즉시 초기화되는 문제를 운영에서 발견해, 같은 Azure DB 기록 내용이 새 객체로 전달될 때 입력 중 초안을 다시 덮어쓰지 않도록 보완했습니다.
- 기존 제작 기록의 빈 통합 메모를 검수 문구로 저장하고 새로고침 후 같은 값을 재조회한 뒤, 원래 빈 값으로 복원·저장·재조회해 검수 흔적이 남지 않은 것을 확인했습니다.

## 2026-07-29 추천 작업 1~5번 일괄 보완
