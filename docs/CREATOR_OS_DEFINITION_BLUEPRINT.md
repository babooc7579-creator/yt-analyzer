# Creator OS Definition Blueprint

> 이 문서는 타임머신 CRM / Creator OS가 무엇을 만들고 있는지 정의하는 기준 문서입니다.
> 앞으로 기능 요청, UI 개편, 데이터 수집 정책, AI 기능 설계를 판단할 때 이 문서를 기준으로 삼습니다.

---

## 1. 제품 정의

타임머신 CRM / Creator OS는 유튜브 레퍼런스를 수집하고, 보관하고, 다시 제작에 활용하기 위한 크리에이터 운영 도구입니다.

이 앱은 단순한 유튜브 영상 목록 조회 도구가 아닙니다. 크리에이터가 매일 참고할 채널과 영상을 관리하고, 오래됐지만 다시 살릴 수 있는 소재를 찾고, 제작 아이디어로 연결하는 개인용 Creator OS입니다.

핵심 흐름은 다음과 같습니다.

```txt
발굴 → 수집 → 보관 → 분석 → 제작 → 축적
```

---

## 2. 핵심 사용자

주 사용자는 비개발자 크리에이터 또는 콘텐츠 운영자입니다.

사용자는 기술 구조보다 다음을 알고 싶어 합니다.

- 오늘 어떤 채널을 봐야 하는지
- 어떤 채널을 새로 수집해야 하는지
- 저장된 영상 중 어떤 소재가 다시 쓸 만한지
- 스크랩한 소재를 어떻게 제작으로 이어갈지
- API 호출이나 비용이 발생하는 작업인지

따라서 화면 문구는 개발자 중심 용어보다 작업 중심 용어를 우선합니다.

---

## 3. Creator OS의 제품 영역

Creator OS는 다음 6개 제품 영역을 기준으로 확장합니다.

### 3.1 디스커버리 탐색

새로운 채널, 주제, 포맷, 영상 흐름을 발견하는 영역입니다.

역할:

- 새로운 레퍼런스 후보 탐색
- 트렌드 흐름 확인
- 채널 결 또는 소재 결 찾기
- 앞으로 수집할 대상을 선별

현재는 준비중 기능이 많을 수 있지만, 제품 지도 안에서는 반드시 보여야 합니다.

### 3.2 레퍼런스 금고

저장된 영상과 스크랩 소재를 확인하는 핵심 보관함입니다.

역할:

- 저장된 영상 조회
- 카드 보기 / 리스트 보기
- 검색, 필터, 정렬
- 스크랩 소재 확인
- 터또터 후보 검토
- AI 리메이크 프롬프트 복사

주의:

- 저장된 영상 불러오기는 DB 조회입니다.
- 새 YouTube API 호출이 발생하지 않는다는 점을 화면에서 명확히 보여야 합니다.

### 3.3 제작 스튜디오

보관한 소재를 실제 제작 후보로 정리하는 영역입니다.

역할:

- 스크랩 소재 검토
- 제작 후보 정리
- 리메이크 방향 정리
- 제목, 도입부, 구성안으로 확장

현재 실제 제작 프로젝트 DB가 없다면, 저장된 것처럼 표현하면 안 됩니다. 준비중 또는 검토 흐름으로 표현합니다.

### 3.4 AI 공방

AI를 활용해 소재를 분석하고 제작 문안으로 바꾸는 영역입니다.

예상 기능:

- 후킹 분석
- 기승전결 분석
- 와우포인트 분석
- 쇼츠 대본 생성
- 제목/썸네일 문구 생성
- 우라까이 재구성 도우미
- 복사 위험 체크

주의:

- AI API가 연결되지 않은 기능은 준비중 안내만 표시합니다.
- 클릭만으로 OpenAI API 호출이 발생하면 안 됩니다.

### 3.5 오퍼레이션 관제

채널을 등록하고, 선택하고, 수집 상태를 확인하는 채널 운영실입니다.

역할:

- 채널 목록 관리
- 새 채널 등록
- 여러 채널 일괄 등록
- 채널 선택/해제
- 선택 채널 수집
- 태그별 수집
- 마지막 수집 상태 확인
- 저장 데이터 조회로 레퍼런스 금고 연결

중요 원칙:

- 채널 선택만으로 YouTube API를 호출하면 안 됩니다.
- 새 영상 수집은 YouTube API 호출입니다.
- 저장된 영상 불러오기는 DB 조회입니다.
- 선택 채널 수집은 체크한 채널을 기준으로 작동해야 합니다.
- 선택된 채널이 없을 때 전체 수집으로 동작한다면, 화면 문구로 반드시 알려야 합니다.

### 3.6 인사이트 / 학습

수집된 데이터에서 패턴과 학습 내용을 쌓는 영역입니다.

역할:

- 채널별 성과 흐름
- 소재 패턴 학습
- 스크랩/제작 결과 회고
- 반복 가능한 콘텐츠 공식 정리

현재는 준비중 안내로 표시할 수 있지만, 장기적으로 Creator OS의 축적 영역입니다.

## 4. 핵심 개념 정의

### 4.1 채널 운영실

채널 운영실은 오퍼레이션 관제의 중심 화면입니다.

사용자가 이 화면에서 이해해야 하는 흐름:

```txt
채널 등록 → 채널 선택 → 선택 채널 새 영상 수집 → 저장된 영상 불러오기 → 레퍼런스 금고 확인
```

채널 운영실은 단순 입력 폼이 아니라 채널 단위 운영 화면이어야 합니다.

권장 UI:

- 상단 요약 카드
- 운영 필터 칩
- 채널별 행 카드
- 왼쪽 채널 정보 카드
- 오른쪽 영상/상태 미리보기 영역
- API 호출과 DB 조회 구분 배지

### 4.2 레퍼런스 금고

레퍼런스 금고는 저장된 영상 자산을 보는 화면입니다.

목표:

- 저장된 영상이 자산처럼 보이게 하기
- 스크랩 소재와 터또터 후보를 빠르게 찾기
- 제작에 활용할 소재를 고르기

### 4.3 터또터 후보

터또터 후보는 이미 과거에 반응이 좋았거나 영상 자체의 힘이 검증된 소재인데, 시간이 지나 알고리즘 노출이 멈춘 영상입니다.

이 후보는 재편집, 재구성, 재업로드를 통해 다시 알고리즘에 태워볼 만한 소재입니다.

보조 설명 예:

- 한 번 반응이 검증된 영상을 재편집해 다시 살리는 후보입니다.
- 시간이 지나 노출이 멈춘 검증된 영상을 다시 살릴 후보입니다.

주의:

- 터또터는 단순히 오래된 영상이 아닙니다.
- 터또터는 단순히 조회수가 높은 영상도 아닙니다.
- 검증된 반응, 경과 시간, 재활용 가능성이 함께 보여야 합니다.

## 5. 데이터 작업 구분 원칙

### 5.1 새 영상 수집

새 영상 수집은 YouTube API 호출이 발생하는 작업입니다.

화면에 반드시 알려야 할 것:

- YouTube API를 호출합니다.
- 새 영상 여부를 확인합니다.
- 이미 저장된 영상은 중복 저장하지 않고 갱신합니다.
- 필요한 채널만 선택해서 실행하는 것이 좋습니다.

### 5.2 저장된 영상 불러오기

저장된 영상 불러오기는 DB 조회입니다.

화면에 반드시 알려야 할 것:

- 이미 저장된 영상만 불러옵니다.
- YouTube API를 새로 호출하지 않습니다.
- 새 영상이 필요하면 수집 기능을 따로 실행해야 합니다.

### 5.3 채널 선택

채널 선택은 수집 또는 조회 대상을 고르는 작업입니다.

주의:

- 채널을 선택하는 것만으로 API 호출이 발생하면 안 됩니다.
- 체크 상태와 실제 수집 범위가 화면 문구와 일치해야 합니다.

---

## 6. 화면 설계 원칙

### 6.1 제품 지도형 사이드바

사이드바는 단순 메뉴가 아니라 Creator OS의 제품 지도입니다.

원칙:

- 현재 가능한 기능과 준비중 기능을 함께 보여줍니다.
- 준비중 기능은 작은 배지로 구분합니다.
- 준비중 기능 클릭 시 API 호출 없이 안내 카드만 보여줍니다.
- 6개 제품 영역의 위계를 유지합니다.

### 6.2 본문 화면

본문은 현재 선택한 제품 영역의 주 작업 공간입니다.

원칙:

- 오퍼레이션 관제에서는 채널 운영실이 주인공이어야 합니다.
- 레퍼런스 금고에서는 영상 보드와 보관함 도구막대가 주인공이어야 합니다.
- 제작 스튜디오에서는 스크랩과 제작 후보 흐름이 주인공이어야 합니다.
- 준비중 화면에서는 현재 변경되는 데이터가 없음을 알려야 합니다.

### 6.3 보조 패널

보조 패널은 주 화면을 대체하면 안 됩니다.

역할:

- 채널 등록
- 세부 설정
- 빠른 작업
- 보조 안내

본문 화면과 같은 제목/요약 카드가 반복되어 사용자를 헷갈리게 하면 안 됩니다.

## 7. UI 톤

Creator OS는 창작자의 콘텐츠 지휘실처럼 보여야 합니다.

권장 톤:

- 다크 네이비
- 차콜
- 슬레이트
- 절제된 인디고/블루/에메랄드 포인트

피해야 할 것:

- 개발자 관리자 페이지처럼 보이는 화면
- 단순 흰색 폼 나열
- 기능 설명만 가득한 화면
- 실제 기능이 없는 것을 완료된 기능처럼 보이게 하는 표현

---

## 8. 기능 구현 판단 기준

새 기능을 만들 때 다음 질문에 답해야 합니다.

- 이 기능은 어느 제품 영역에 속하는가?
- 사용자가 누르기 전에 API 호출 여부를 알 수 있는가?
- 기존 저장/수집/조회 로직을 바꾸는가?
- 새 DB 구조가 필요한가?
- 준비중 기능을 실제 기능처럼 오해하게 만들지는 않는가?
- 비개발자가 결과를 이해할 수 있는가?

---

## 9. 금지 원칙

- 기존 기능 삭제 금지
- 기존 API 주소 삭제 금지
- 채널 선택만으로 YouTube API 호출 금지
- 비용이 발생할 수 있는 반복 자동 수집 추가 금지
- 저장 데이터 조회와 새 영상 수집 혼동 금지
- 실제 저장 기능이 없는 제작 후보를 저장 완료처럼 표현 금지
- localStorage key 임의 변경 금지
- package.json 변경 없이 가능한 UI 작업은 새 라이브러리 추가 금지

## 10. 단계별 제품 방향

### Phase 1. 제품 지도 확립

- Creator OS 사이드바
- 오늘의 레이더 홈
- 레퍼런스 금고 1차 정리
- 오퍼레이션 관제 채널 운영실

### Phase 2. 데이터 흐름 명확화

- 선택 채널 수집 범위 표시
- 저장 데이터 조회와 API 수집 분리
- 마지막 수집 상태 표시
- 수집 로그 정책 설계

### Phase 3. 소재 판단 강화

- 터또터 후보 설명 강화
- 스크랩 소재 흐름 정리
- 채널별 영상 흐름 미리보기
- 제작 후보 검토 흐름 설계

### Phase 4. 제작 연결

- AI 공방 기능 연결
- 제작 후보함 설계
- 제목/대본/후킹 분석 템플릿
- 복사 위험 체크

### Phase 5. 학습과 축적

- 채널별 운영 인사이트
- 소재 패턴 DB
- 제작 결과 회고
- 반복 가능한 콘텐츠 공식화

## 11. 보고 기준

작업 결과는 비개발자도 이해할 수 있게 보고합니다.

권장 형식:

- 변경한 것
- 바뀐 이유
- 확인 방법
- 주의할 점
- 다음 추천 작업

특히 다음은 반드시 구분해서 설명합니다.

- YouTube API 호출이 발생하는 작업
- DB 조회만 하는 작업
- 화면 문구만 바뀐 작업
- 실제 저장/수집 로직이 바뀐 작업
